# Student workflow — IDE, run, and submit

## Editor

- You edit files in a **web IDE** (Monaco-based in the product).
- **Save** often; the platform may **auto-save** and keep a **version history** (see [Timeline](timeline.md)).
- You **do not** run raw Git commands—history is **managed for you**.

## Run

- **Run** sends code to a **sandbox** (e.g. Judge0) through the **backend**.
- **Output** (stdout/stderr) appears in the console area.
- **Run logs** may be retained for integrity—see [Data collected](../../transparency/data-collected.md).

### HTML / UI previews

- Some courses use an **HTML preview** pane; interactive pages may be sandboxed in an iframe.

## Submit

- Use **Submit** when your work is final for that attempt (unless your instructor allows multiple attempts).
- After submit, policy may **lock** editing—confirm in your syllabus.

## Fair use

- Do not attempt to **spoof** identity or tamper with telemetry—your institution’s integrity policy applies.
