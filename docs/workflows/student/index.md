# Student workflows — overview

Students use ProctorIDE to **see what is due**, **work in a browser IDE** with **saved history**, **run code safely**, and **submit** to their instructor.

## Golden path

1. [Dashboard](dashboard.md) — find the activity.
2. [Start the activity](starting-activity.md) — read any **transparency** notice.
3. [Use the IDE, run, submit](ide-run-submit.md) — complete your work.
4. Use [Timeline](timeline.md) to recover from mistakes.
5. [Comments](comments.md) if your course enables discussion on code lines.

## By activity type

| Type | What to expect |
|------|----------------|
| Assignment / project | More files, more iterations, **moderate** logging of work patterns. |
| Challenge | Lighter logging; still follow course rules. |
| Quiz | Shorter, often stricter time or navigation rules. |
| Test / exam | **Strongest** monitoring; read disclosures carefully. |
