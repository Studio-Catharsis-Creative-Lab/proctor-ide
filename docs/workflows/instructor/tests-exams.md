# Instructor workflow — tests and exams

**Tests** and **exams** are **high-stakes**. ProctorIDE’s architecture supports **stronger integrity signals**; your institution decides which layers are enabled (technical monitoring, human proctoring, lockdown browsers, etc.).

## Planning

- Clarify **what is allowed**: references, notes, IDE features, internet.
- Align **tracking level** to **comprehensive** when using platform logging broadly.
- Coordinate with **testing center** or **online proctoring** if applicable—the product may integrate signals but **does not replace** institutional exam policy.

## Configuration checklist

- [ ] Activity labeled clearly as **exam** in the UI.
- [ ] **Due / availability window** matches registrar or department rules.
- [ ] **Accommodations** handled per disability services (extended time, breaks)—often manual overrides outside MVP scope.
- [ ] **Transparency**: students must see a **plain-language** summary before starting.

## During the window

- Monitor for **spikes** in support tickets (auth, disconnects).
- Have a **communications channel** (course forum) for technical escalation.

## After the window

- Lock submissions per policy.
- Review integrity bundles: **timeline**, **runs**, **tracking events** as enabled.
- Follow academic integrity **due process**—automated signals are **not** standalone proof.
